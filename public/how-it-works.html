How it works

Three ways to connect. One app. No accounts, no uploads, no storage.

  1. 1
    Same WiFi — automatic

    Open SdfDrop on both devices. The server groups devices on the same network (public IPv4, IPv6 /64 prefix, private /24) and each side instantly lists the other on its radar. Nothing to type, no code.

  2. 2
    Different networks — room code

    Tap Room, enter the same 4–12 letter code (e.g. BEACH42) on both devices — or scan the QR. Both join the room and see each other even across mobile data, hotspots and VPNs.

  3. 3
    Tap a device and send

    Pick files or text. The other side taps Accept. Files fly over an encrypted WebRTC DataChannel with live progress and speed. P2P blocked? Traffic relays through the server automatically.

Under the hood

  1. A
    Signaling only

    Devices exchange WebRTC offers, answers and ICE candidates through the server over WebSocket. The server never stores your files.

  2. B
    Direct P2P first

    16KB DataChannel chunks with backpressure, DTLS encrypted end-to-end. STUN plus OpenRelay TURN help punch through NATs.

  3. C
    Relay fallback

    Symmetric NAT or VPN blocking P2P? Chunks relay over WebSocket (100MB cap per file, header-before-chunks sessions, sequence checks).

  4. D
    Room broadcast

    Teachers send once — the server fans the transfer out to every room member. Accepts are counted live before the send.
